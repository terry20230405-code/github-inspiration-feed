# 固定质量测试仓库集

这五个仓库是 `github-inspiration-editor` 的固定“考题”。它们不是下一批待发布项目，也不会因为测试而自动进入页面。选择它们是因为它们覆盖了当前产品最容易写坏的不同类型，而不是因为 Star 数量或项目排名。

## 使用规则

- 固定的是仓库和测试重点，不是会持续变化的 Star、Fork 或版本号。
- 每次 A/B 比较必须为同一个仓库使用同一份研究笔记和同一批来源快照。
- 当前页面文案只能当作旧版输出，不能反过来当成仓库事实。
- 测试产物保存在 `outputs/evaluations/`，不要写入 `src/data/` 的产品数据，也不要混入 `outputs/generated/` 的待发布草稿。
- 只有产品内容定位明显改变时才更换测试仓库；更换时提升本文件的版本号并说明原因。

测试集版本：`1`

## B1 — remotion-dev/remotion

- 仓库：https://github.com/remotion-dev/remotion
- 类型：用代码生成视频的开发框架。
- 主要测试：能否把“React 组件、逐帧控制、渲染”讲成小白能想象的产品工作方式。
- 容易犯错：把框架直接描述成无需编程的视频工具；把所有方向都写成营销视频生成器；只列技术栈而没有输入与结果。
- 好结果应体现：现有能力与上层无代码产品之间的边界，以及视频能力在创作、教育、个人记录等不同场景中的复用。

## B2 — excalidraw/excalidraw

- 仓库：https://github.com/excalidraw/excalidraw
- 类型：手绘风格的画布与协作工具。
- 主要测试：面对读者熟悉的“白板”，能否抓住画布、场景数据、协作与导出等可复用能力，而不是写一段通用白板介绍。
- 容易犯错：所有方向只是换一套模板；把“加 AI”当作产品差异；忽略多人、结构化关系或输出形式的变化。
- 好结果应体现：不同方向具有不同输入、使用频率、协作方式和最终产物。

## B3 — immich-app/immich

- 仓库：https://github.com/immich-app/immich
- 类型：自托管照片与视频管理产品。
- 主要测试：能否同时讲清备份、整理、搜索、人物地点信息和自托管，并谨慎处理隐私、部署与许可证。
- 容易犯错：把自托管等同于简单或绝对安全；声称可以不受限制地复用；所有方向仍然只是相册备份。
- 好结果应体现：原项目事实、产品推断和新方向之间的边界，以及照片时间、地点、人物等信息可以形成的新体验。

## B4 — n8n-io/n8n

- 仓库：https://github.com/n8n-io/n8n
- 类型：可视化工作流自动化平台。
- 主要测试：能否把节点、触发器、条件和动作翻译成普通人能理解的自动工作流程，并准确处理其许可证性质。
- 容易犯错：简单称为可任意商用的开源项目；堆砌连接器数量；把所有方向写成面向商家的效率或营销 SaaS。
- 好结果应体现：隐藏通用配置后形成专用产品的逻辑，同时保留个人、创作者、社区或生活场景的可能性。

## B5 — usememos/memos

- 仓库：https://github.com/usememos/memos
- 类型：时间线式、自托管的轻量笔记产品。
- 主要测试：面对一个相对简单的产品，能否保持信息密度而不在多个字段重复“快速记录、数据自主”。
- 容易犯错：把输入方式的小变化当作完整新产品；方向全部是不同人群的笔记应用；为了显得复杂而加入不必要的技术细节。
- 好结果应体现：记录入口、回顾机制、多人关系或输出结果发生实质变化，并保持简洁。
- 当前可复用证据样本：`outputs/generated/usememos-memos.research.md`。

## 覆盖范围

这五个案例共同覆盖：

- 开发框架、终端产品和通用平台。
- 视频、画布、照片、自动化和文字记录。
- MIT、AGPL 和非标准开放许可证带来的不同表达风险。
- 技术型读者、普通个人、家庭、创作者、团队与商家等不同用户语境。
- 容易商业化偏置、容易同质化、容易技术化和容易过度推断的内容类型。

如果一次 Skill 修改在这五类项目上都保持稳定，它更有可能适用于未来持续增长的仓库灵感流。
