# 后续自动化总控评估

- 日期：2026-08-27
- 评估范围：阶段六、阶段七、工程检查的总控编排
- 发布副作用：无

## 必须成立的边界

1. 只检查模式不能出现 `--write`。
2. 阶段六发现关键变化后，不能写仓库快照，也不能启动阶段七。
3. 阶段七 dry-run 发现关键来源问题后，不能写来源状态。
4. 普通来源变化应停在 `ai-review-required`，不能授权发布。
5. 有效审核要求修改内容时，应停在 `content-draft-required`，只允许生成候选草稿。
6. 技术命令失败时必须输出 `failed`，不能继续伪装成功。
7. 并发锁必须阻止两个刷新周期同时运行。
8. Windows 环境必须解析实际的 `npm.CMD`。

## 测试结果

总控分支测试全部通过。真实 `npm run refresh:cycle` dry-run 也已完成：阶段六检查 4 个项目，阶段七深查 3 个活动项目，来源指纹均未变化；没有写入产品快照，`publicationAuthorized` 保持 `false`。

真实预演还暴露并修复了两个 Windows 集成问题：子进程需要解析 `npm.CMD`，报告终端副本需要避开 GBK 无法输出的 Vite `✓` 符号。

## 结论

自动化总控能够在阶段六、阶段七和 AI 之间交接工作；其正式写入现在由阶段八版本快照保护。定时频率和公网部署仍需单独决定。
